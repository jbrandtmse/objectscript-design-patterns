### Test Framework Architecture
[Source: architecture/test-strategy.md]

The testing framework uses %UnitTest as the base, with custom extensions:

**Base Test Class Structure:**
```objectscript
Class Patterns.Test.TestCase Extends %UnitTest.TestCase
{
    Property PatternInstance As %RegisteredObject;
    Property TestData As %DynamicObject;
    Property Metrics As %DynamicObject;
    
    Method OnBeforeOneTest() As %Status
    Method OnAfterOneTest() As %Status
    Method AssertPatternContract(pPattern As %RegisteredObject, pContract As %String) As %Boolean
    Method AssertPerformance(pOperation As %String, pMaxTime As %Integer) As %Boolean
}
```

### Test Organization Structure
[Source: architecture/source-tree.md]

Tests must be organized under /src/Patterns/Test/ with this structure:
- `/src/Patterns/Test/Unit/` - Unit tests mirroring source structure
- `/src/Patterns/Test/Integration/` - Integration and cross-pattern tests
- `/src/Patterns/Test/Performance/` - Benchmark and performance tests
- `/src/Patterns/Test/Fixtures/` - Test data generators and mock objects

### Testing Standards
[Source: architecture/coding-standards.md]

**Naming Conventions:**
- Test classes: Suffix with `Test` (e.g., SingletonTest, FactoryPatternTest)
- Test methods: Prefix with `Test` (e.g., TestCreateInstance(), TestErrorHandling())
- Test namespace mirrors source structure

**Test Structure Pattern:**
```objectscript
Method TestPatternBehavior() As %Boolean
{
    // Arrange
    Set pattern = ##class(Pattern).%New()
    Set expectedResult = "Success"
    
    // Act
    Set actualResult = pattern.Execute()
    
    // Assert
    Do ..AssertEquals(actualResult, expectedResult, "Pattern should return success")
    
    // Cleanup
    Do pattern.%Close()
    
    Return 1
}
```

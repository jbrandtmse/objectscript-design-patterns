### Special Case Pattern Specific Considerations

- **Polymorphism**: Special cases implement same interface as real objects
- **Null Elimination**: Replace null checks with polymorphic behavior
- **Safe Defaults**: Special cases provide safe default behaviors
- **Detection**: IsNull() or IsSpecialCase() methods for identification
- **Variants**: Null Object, Unknown Case, Default Case
- **Client Simplification**: Eliminate conditional logic in client code
- **Factory Pattern**: Use factories to create appropriate cases
- **Immutability**: Special cases typically immutable

### Special Case Implementation Patterns

[Source: architecture/coding-standards.md]

**Null Object Pattern:**
```objectscript
Class NullPatient Extends Patient
{
    Method IsNull() As %Boolean
    {
        Quit 1
    }
    
    Method GetDisplayName() As %String
    {
        Quit "Unknown Patient"
    }
    
    Method GetMRN() As %String
    {
        Quit "UNKNOWN"
    }
    
    Method Save() As %Status
    {
        // Safe no-op for null patient
        Quit $$$OK
    }
}
```

**Unknown Case Pattern:**
```objectscript
Class UnknownPatient Extends Patient
{
    Method IsSpecialCase() As %Boolean
    {
        Quit 1
    }
    
    Method GetDisplayName() As %String
    {
        Quit "Unregistered Patient"
    }
    
    Method GetMRN() As %String
    {
        // Generate temporary MRN
        Quit "TEMP-" _ $ZUTIL(68,40,1)
    }
}
```

**Client Code Without Null Checks:**
```objectscript
// Before: Null checks everywhere
Method ProcessPatient(pPatient As Patient) As %Status
{
    If '$IsObject(pPatient) {
        // Handle null
        Quit $$$OK
    }
    
    Set tName = pPatient.GetDisplayName()
    // ...
}

// After: No null checks needed
Method ProcessPatient(pPatient As Patient) As %Status
{
    // Works with real patient or null object
    Set tName = pPatient.GetDisplayName()
    // ...
}
```

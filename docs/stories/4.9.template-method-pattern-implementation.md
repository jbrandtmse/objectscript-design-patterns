### Class Structure Template for Template Method Pattern

[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four Template Method Pattern - Define Algorithm Skeleton
Class Patterns.GoF.Behavioral.TemplateMethod Extends %RegisteredObject [ Abstract ]
{
    /// Template method defining algorithm skeleton - CANNOT be overridden
    Method Execute() As %Status [ Final ]
    {
        Set tSC = $$$OK
        
        Try {
            // Step 1: Initialize (hook method)
            Do ..Initialize()
            
            // Step 2: Primitive operation (abstract - must override)
            Set tSC = ..PrimitiveOperation1()
            If $$$ISERR(tSC) Quit
            
            // Step 3: Concrete operation (provided by base class)
            Do ..ConcreteOperation()
            
            // Step 4: Primitive operation (abstract - must override)  
            Set tSC = ..PrimitiveOperation2()
            If $$$ISERR(tSC) Quit
            
            // Step 5: Hook method (optional override)
            If ..Hook() {
                Do ..OptionalOperation()
            }
            
            // Step 6: Finalize (hook method)
            Do ..Finalize()
            
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        
        Quit tSC
    }
    
    /// Hook method - can be overridden
    Method Initialize()
    {
        // Default implementation (can be empty)
    }
    
    /// Abstract primitive operation - must be overridden
    Method PrimitiveOperation1() As %Status [ Abstract ]
    {
        Quit $$$OK
    }
    
    /// Concrete operation - provided by base class
    Method ConcreteOperation() [ Private ]
    {
        // Implementation that all subclasses share
    }
    
    /// Abstract primitive operation - must be overridden
    Method PrimitiveOperation2() As %Status [ Abstract ]
    {
        Quit $$$OK
    }
    
    /// Hook method returning boolean for conditional behavior
    Method Hook() As %Boolean
    {
        Quit 1  // Default is true
    }
    
    /// Optional operation controlled by hook
    Method OptionalOperation()
    {
        // Implementation for optional step
    }
    
    /// Hook method for cleanup
    Method Finalize()
    {
        // Default cleanup (can be empty)
    }
}
```

### Template Method Pattern Specific Considerations

- **Algorithm Invariance**: Template method must be [ Final ] to prevent override
- **Primitive Operations**: Abstract methods that subclasses must implement
- **Hook Methods**: Optional methods with default implementations
- **Concrete Operations**: Private methods providing common functionality
- **Step Order**: Algorithm skeleton defines immutable step sequence
- **Hollywood Principle**: "Don't call us, we'll call you" - base class controls flow
- **Extension Points**: Hooks provide controlled customization
- **Method Visibility**: Careful use of public, private, and protected

### ObjectScript-Specific Template Method Features

[Source: architecture/coding-standards.md]
- **Final Methods**: Use [ Final ] keyword to prevent override
- **Abstract Classes**: Use [ Abstract ] keyword for base classes
- **Abstract Methods**: Must have body with return value in ObjectScript
- **Method Overriding**: Subclasses use same method signature
- **Super Calls**: Use ##super() to call parent implementation
- **Class Hierarchy**: Use %IsA() to check inheritance
- **Dynamic Dispatch**: Automatic based on object type
- **Method Keywords**: Private, Final, Abstract affect inheritance

### Template Method vs Strategy Pattern Differences

- **Template Method**: Defines algorithm skeleton, subclasses fill in steps
- **Strategy**: Encapsulates entire algorithms, client chooses which to use
- **Template Method**: Inheritance-based (is-a relationship)
- **Strategy**: Composition-based (has-a relationship)
- **Template Method**: Algorithm structure fixed, steps variable
- **Strategy**: Entire algorithm variable
- **Template Method**: Compile-time binding via inheritance
- **Strategy**: Runtime binding via composition

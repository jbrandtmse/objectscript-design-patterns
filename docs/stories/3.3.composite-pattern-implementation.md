### Class Structure Template for Composite Pattern
[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four Composite Pattern - Component
Class Patterns.GoF.Structural.Component Extends %RegisteredObject [ Abstract ]
{
    /// Name of the component
    Property Name As %String;
    
    /// Parent reference for bidirectional navigation
    Property Parent As Component;
    
    /// Perform operation on component
    Method Operation() As %String [ Abstract ]
    {
        Quit ""
    }
    
    /// Add child component - default throws error for leaves
    Method Add(pComponent As Component) As %Status
    {
        Quit $$$ERROR($$$GeneralError, "Cannot add to leaf component")
    }
    
    /// Remove child component - default throws error for leaves
    Method Remove(pComponent As Component) As %Status
    {
        Quit $$$ERROR($$$GeneralError, "Cannot remove from leaf component")
    }
    
    /// Get child at index - default returns null for leaves
    Method GetChild(pIndex As %Integer) As Component
    {
        Quit ""
    }
}
```

### Composite Pattern Specific Considerations
- **Transparency vs Safety**: Choose between uniform interface (all methods in Component) or type-safe approach
- **Child Management**: Use %Collection.ListOfObj for efficient child storage
- **Parent References**: Maintain bidirectional references for tree navigation
- **Memory Management**: Consider weak references for large trees to prevent memory issues
- **Global Storage**: Use hierarchical global structure for persistence
- **Performance**: Implement lazy loading for large tree structures
- **Thread Safety**: Ensure tree modifications are thread-safe if used concurrently

### ObjectScript Tree Storage Pattern
```objectscript
// Global structure for tree storage
^TreeStorage(treeName, nodeId) = $listbuild(name, type, parentId)
^TreeStorage(treeName, nodeId, "children") = $listbuild(childId1, childId2, ...)
^TreeStorage(treeName, nodeId, "data", property) = value
```

### Class Structure Template for State Pattern
[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four State Pattern - State-Dependent Behavior
Class Patterns.GoF.Behavioral.State Extends %RegisteredObject [ Abstract ]
{
    /// Handle request in this state
    Method Handle(pContext As StateContext, pRequest As %String) [ Abstract ]
    {
        Quit ""
    }
    
    /// Called when entering this state
    Method OnEntry(pContext As StateContext) As %Status
    {
        Quit $$$OK
    }
    
    /// Called when exiting this state
    Method OnExit(pContext As StateContext) As %Status
    {
        Quit $$$OK
    }
}

/// Context that maintains current state
Class Patterns.GoF.Behavioral.StateContext Extends %RegisteredObject
{
    /// Current state instance
    Property CurrentState As State;
    
    /// State history for tracking
    Property StateHistory As list Of %String;
    
    /// Transition to new state
    Method TransitionTo(pNewState As State) As %Status
    {
        Set tSC = $$$OK
        
        // Exit current state
        If $IsObject(..CurrentState) {
            Set tSC = ..CurrentState.OnExit($this)
            If $$$ISERR(tSC) Quit tSC
        }
        
        // Record history
        Do ..StateHistory.Insert(pNewState.%ClassName(1))
        
        // Enter new state
        Set ..CurrentState = pNewState
        Set tSC = pNewState.OnEntry($this)
        
        Quit tSC
    }
    
    /// Delegate request to current state
    Method Request(pRequest As %String)
    {
        If $IsObject(..CurrentState) {
            Do ..CurrentState.Handle($this, pRequest)
        }
    }
}
```

### State Pattern Specific Considerations
- **State Encapsulation**: Each state encapsulates its behavior
- **State Transitions**: Context or states can trigger transitions
- **State Explosion**: Be mindful of number of states
- **Transition Validation**: Ensure valid state transitions
- **State Persistence**: Consider saving/restoring state
- **Concurrency**: Handle concurrent state changes
- **State History**: Track state changes for debugging
- **Performance**: Minimize transition overhead

### ObjectScript-Specific State Machine Features
[Source: architecture/coding-standards.md]
- **Abstract Classes**: Use [ Abstract ] keyword
- **Method Dispatch**: Use $METHOD for dynamic calls
- **Class Introspection**: Use %Dictionary classes
- **Event Handling**: Implement callback mechanism
- **Global Storage**: Use for persistent state
- **Job/Process State**: Handle multi-process scenarios
- **Lock Management**: Ensure state consistency
- **Transaction Support**: Atomic state changes

### Healthcare Patient Admission Workflow Requirements
- **Pre-Admission**: Insurance verification, consent forms
- **Registration**: Patient demographics, contact info
- **Triage**: Initial assessment, priority assignment
- **Consultation**: Doctor examination, diagnosis
- **Treatment**: Medical procedures, medications
- **Discharge**: Final documentation, follow-up scheduling
- **State Rules**: Valid transitions between admission states
- **Audit Requirements**: Track all state changes with timestamp
- **Error Recovery**: Handle invalid state transitions
- **Timeout Handling**: Auto-transition on timeouts

### State Transition Rules Design
- **Guard Conditions**: Prerequisites for transitions
- **Transition Actions**: Operations during transition
- **Entry Actions**: Operations when entering state
- **Exit Actions**: Operations when leaving state
- **Self-Transitions**: State can transition to itself
- **Automatic Transitions**: Condition-based transitions
- **Manual Transitions**: User-triggered transitions
- **Forced Transitions**: System override transitions

### Class Structure Template for Proxy Pattern
[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four Proxy Pattern - Access Control
Class Patterns.GoF.Structural.Subject Extends %RegisteredObject
{
    /// Interface method that both Proxy and RealSubject implement
    Method Request() As %String [ Abstract ]
    {
        Quit ""
    }
}

/// Real subject containing actual functionality
Class Patterns.GoF.Structural.RealSubject Extends Subject
{
    Method Request() As %String
    {
        Quit "RealSubject: Handling request"
    }
}

/// Proxy controlling access to RealSubject
Class Patterns.GoF.Structural.Proxy Extends Subject
{
    Property RealSubject As RealSubject;
    
    Method Request() As %String
    {
        If ..CheckAccess() {
            If '..IsLoaded() {
                Do ..LoadRealSubject()
            }
            Do ..LogAccess()
            Quit ..RealSubject.Request()
        }
        Quit "Access Denied"
    }
    
    Method CheckAccess() As %Boolean [ Abstract ]
    {
        Quit 1
    }
}
```

### Proxy Pattern Specific Considerations
- **Virtual Proxy**: Lazy loading for expensive objects (images, documents)
- **Protection Proxy**: Access control based on user roles and permissions
- **Remote Proxy**: Local representative for remote objects
- **IRIS Security Integration**: Use $USERNAME, $ROLES for authorization
- **Audit Logging**: Track all access attempts for compliance
- **Thread Safety**: Ensure lazy initialization is thread-safe
- **Performance**: Virtual proxy reduces memory and startup time
- **Transparency**: Proxy must implement same interface as real subject

### IRIS Security Features to Use
- **$USERNAME**: Current logged-in user
- **$ROLES**: Comma-separated list of user's roles
- **$SYSTEM.Security.Check()**: Check specific resource permissions
- **%SYS.Audit**: Log security-relevant events
- **Resources**: Define protected operations as IRIS resources
- **Roles**: Map user groups to permissions

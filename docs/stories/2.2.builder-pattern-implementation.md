### Implementation Notes
[Source: architecture/coding-standards.md]
- Use PascalCase for class names and public methods
- Parameters prefix with 'p' (e.g., pReportType, pPatientId)
- Local variables prefix with 't' (e.g., tBuilder, tProduct)
- Properties use PascalCase with no prefix
- Abstract classes use [ Abstract ] keyword
- Implement %OnNew() constructor for initialization
- Use Try/Catch blocks for robust error handling
- Return %Status from methods that don't return objects

### Fluent Interface in ObjectScript
[Source: architecture/coding-standards.md]
- Methods return $THIS (current instance) to enable chaining
- Example pattern:
  ```objectscript
  Method SetTitle(pTitle As %String) As Builder
  {
      Set ..Title = pTitle
      Quit $THIS
  }
  ```
- Validate inputs but maintain chain by returning $THIS even on errors
- Consider storing validation errors for later retrieval

### Builder vs Abstract Factory
Key differences to document:
- Builder focuses on step-by-step construction of a single complex object
- Abstract Factory creates families of related objects
- Builder often uses fluent interface for readable construction code
- Director encapsulates construction algorithms, factory doesn't
- Builder useful when object creation has many optional parameters

### ObjectScript Property Handling
[Source: architecture/coding-standards.md]
- Properties defined with datatype: `Property Title As %String`
- Optional properties can use default values: `Property Priority As %Integer [ InitialExpression = 3 ]`
- Calculated properties: `Property FullName As %String [ Calculated ]`
- Private properties prefix with %: `Property %InternalState As %String [ Private ]`
- Collection properties: `Property Sections As list Of %String`
- Use $ISOBJECT() to check if object properties are set
- Validate property values in setter methods when needed

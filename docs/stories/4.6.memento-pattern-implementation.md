### Class Structure Template for Memento Pattern
[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four Memento Pattern - State Capture and Restoration
Class Patterns.GoF.Behavioral.Memento Extends %RegisteredObject
{
    /// Private state storage (should not be accessible externally)
    Property %State As %String [ Private ];
    
    /// Timestamp when memento was created
    Property Timestamp As %TimeStamp [ InitialExpression = {$ZDATETIME($HOROLOG, 3)} ];
    
    /// Constructor - package private to prevent external creation
    Method %OnNew(pState As %String) As %Status [ Private ]
    {
        Set ..%State = pState
        Quit $$$OK
    }
    
    /// Get state - package private for Originator access only
    Method GetState() As %String [ Private ]
    {
        Quit ..%State
    }
}

/// Originator that creates and restores from mementos
Class Patterns.GoF.Behavioral.Originator Extends %RegisteredObject
{
    /// Current state to be saved/restored
    Property State As %String;
    
    /// Create memento of current state
    Method CreateMemento() As Memento
    {
        Quit ##class(Memento).%New(..State)
    }
    
    /// Restore state from memento
    Method RestoreFromMemento(pMemento As Memento) As %Status
    {
        Set ..State = pMemento.GetState()
        Quit $$$OK
    }
}

/// Caretaker that manages mementos
Class Patterns.GoF.Behavioral.Caretaker Extends %RegisteredObject
{
    /// Collection of saved mementos
    Property Mementos As list Of Memento;
    
    /// Add memento to history
    Method AddMemento(pMemento As Memento) As %Status
    {
        Do ..Mementos.Insert(pMemento)
        Quit $$$OK
    }
    
    /// Get memento by index
    Method GetMemento(pIndex As %Integer) As Memento
    {
        Quit ..Mementos.GetAt(pIndex)
    }
}
```

### Memento Pattern Specific Considerations
- **Encapsulation**: Memento internals must be hidden from all except Originator
- **Storage Size**: Consider memory implications of storing many states
- **Serialization**: Complex objects need proper serialization strategy
- **Versioning**: Handle schema changes between save and restore
- **Compression**: Large states may benefit from compression
- **Persistence**: Choose between memory, disk, or global storage
- **Concurrency**: Handle simultaneous access to shared mementos
- **Privacy**: Ensure sensitive data in mementos is protected

### ObjectScript-Specific Serialization Features
[Source: architecture/coding-standards.md]
- **%SerializeObject**: Built-in object serialization to string
- **%JSONExport/%JSONImport**: JSON serialization for objects
- **%Save/%Open**: Persistent class storage mechanism
- **$LISTBUILD/$LISTGET**: Efficient list serialization
- **Globals**: Native hierarchical storage for complex states
- **%Stream**: For large state storage
- **%Binary**: Binary serialization for performance
- **XML Export/Import**: Alternative serialization format

### Healthcare Patient Record Versioning Requirements
- **Audit Trail**: Complete history of all changes with timestamps
- **Regulatory Compliance**: HIPAA, GDPR requirements for data versioning
- **Rollback Capability**: Restore to any previous version
- **Comparison Tools**: View differences between versions
- **Access Control**: Version-level security permissions
- **Retention Policies**: Automatic archival/deletion schedules
- **Legal Hold**: Prevent deletion of certain versions
- **Change Attribution**: Track user, reason, authorization for changes
- **Snapshot Triggers**: Automatic versioning on specific events
- **Storage Optimization**: Incremental/delta storage for efficiency

### State Storage Strategies
- **Memory-based**: Fast but limited by available RAM
  ```objectscript
  Property MementoCache As list Of Memento;
  ```
- **Global-based**: Persistent and scalable
  ```objectscript
  Set ^Patterns.Memento(id, checkpoint) = state
  ```
- **Stream-based**: For very large states
  ```objectscript
  Set stream = ##class(%Stream.GlobalCharacter).%New()
  Do stream.Write(state)
  ```
- **Hybrid**: Recent in memory, older on disk
- **Compressed**: Reduce storage requirements
- **Encrypted**: Protect sensitive state data

### Checkpoint Management Design
- **Naming Convention**: Timestamp-based or user-defined names
- **Limit Strategies**: Maximum count, age-based, size-based
- **Pruning Policies**: FIFO, LRU, priority-based
- **Metadata**: Store context with each checkpoint
- **Branching**: Support for alternate timelines
- **Tagging**: Mark important checkpoints
- **Comparison**: Built-in diff capabilities

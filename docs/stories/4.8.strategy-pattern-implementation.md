### Class Structure Template for Strategy Pattern
[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four Strategy Pattern - Encapsulate Algorithms
Class Patterns.GoF.Behavioral.Strategy Extends %RegisteredObject [ Abstract ]
{
    /// Execute the strategy algorithm
    Method Execute(pContext As %RegisteredObject, pData As %RegisteredObject) [ Abstract ]
    {
        Quit ""
    }
    
    /// Validate if strategy can handle the data
    Method CanHandle(pData As %RegisteredObject) As %Boolean
    {
        Quit 1
    }
    
    /// Get strategy performance metrics
    Method GetMetrics() As %DynamicObject
    {
        Quit {}
    }
}

/// Context that uses strategies
Class Patterns.GoF.Behavioral.StrategyContext Extends %RegisteredObject
{
    /// Current strategy instance
    Property CurrentStrategy As Strategy;
    
    /// Strategy cache for performance
    Property StrategyCache As %ArrayOfObjects [ Private ];
    
    /// Set the strategy to use
    Method SetStrategy(pStrategy As Strategy) As %Status
    {
        Set tSC = $$$OK
        
        If '$IsObject(pStrategy) {
            Quit $$$ERROR($$$GeneralError, "Invalid strategy object")
        }
        
        Set ..CurrentStrategy = pStrategy
        
        Quit tSC
    }
    
    /// Execute using current strategy
    Method ExecuteStrategy(pData As %RegisteredObject) As %String
    {
        If '$IsObject(..CurrentStrategy) {
            Quit ""
        }
        
        Quit ..CurrentStrategy.Execute($this, pData)
    }
    
    /// Select strategy based on criteria
    Method SelectStrategy(pCriteria As %String) As %Status
    {
        // Implementation to select appropriate strategy
        Quit $$$OK
    }
}
```

### Strategy Pattern Specific Considerations
- **Algorithm Encapsulation**: Each strategy encapsulates an algorithm
- **Runtime Selection**: Strategies can be swapped at runtime
- **Context Independence**: Strategies should not depend on context internals
- **Performance**: Consider caching strategy instances
- **Validation**: Strategies should validate they can handle the data
- **Composition**: Allow composite strategies for complex scenarios
- **Thread Safety**: Ensure strategies are thread-safe
- **Configuration**: Support external strategy configuration

### ObjectScript-Specific Strategy Features
[Source: architecture/coding-standards.md]
- **Abstract Classes**: Use [ Abstract ] keyword
- **Method Dispatch**: Use $METHOD for dynamic calls
- **Class Introspection**: Use %Dictionary classes
- **Polymorphism**: Leverage %IsA() for type checking
- **Performance**: Cache strategy instances
- **Dynamic Loading**: Use $CLASSMETHOD for factory
- **Configuration**: Store in globals or %Persistent
- **Metrics**: Track execution times and usage

- **Data Type**: Select based on input data type
- **Business Rules**: Apply rule-based selection

### Key Implementation Notes for Strategy Pattern
- Primary focus: Encapsulating interchangeable algorithms
- Runtime selection should be efficient and flexible
- Healthcare context: Critical for billing calculations with multiple payer types
- Consider relationship with State pattern (behavior vs algorithm focus)
- Strategy can be stateless (unlike State pattern)
- Implement strategy registry for available strategies
- Document when to use Strategy vs Template Method
- Consider performance implications of strategy switching

### Differences from State Pattern
- **Strategy**: Focuses on algorithms, client chooses strategy
- **State**: Focuses on object state, transitions handled internally
- **Strategy**: Typically stateless, interchangeable
- **State**: Maintains state, controls transitions
- **Strategy**: Client aware of strategies
- **State**: Client unaware of states

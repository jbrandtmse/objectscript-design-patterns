### Row Data Gateway Pattern Specific Considerations

- **One Instance Per Row**: Each gateway instance represents a single database row
- **Stateful Design**: Unlike Table Data Gateway, row gateways maintain state
- **CRUD Methods**: Instance methods Save(), Delete(), Refresh() operate on the row
- **Finder Methods**: Class methods return gateway instances (FindById, FindByX)
- **Dirty Tracking**: Track property changes to optimize updates
- **New vs Existing**: IsNew() determines if row exists in database
- **Property Accessors**: Properties map directly to database columns
- **No Business Logic**: Gateways contain only data access code, no domain rules
- **Transaction Participation**: Gateways participate in caller-managed transactions
- **Concurrency**: Multiple instances can represent same row (careful with updates)

### IRIS Embedded SQL Features for Row Gateway

[Source: architecture/tech-stack.md, coding-standards.md]
- **&sql() Tag**: Use embedded SQL syntax for single-row operations
- **%ROWID**: System property for unique row identifier
- **SQLCODE**: Check after each SQL operation (0 = success, 100 = no data, <0 = error)
- **Parameterized Queries**: Use :paramName syntax for SQL injection prevention
- **%Persistent Classes**: Leverage existing persistent classes or SQL projections
- **Dynamic Properties**: Use properties to represent database columns
- **Object Opening**: Use %OpenId() to load persistent objects by ID
- **Object Saving**: Use %Save() to persist object changes
- **Object Deleting**: Use %DeleteId() to remove rows

### Row Data Gateway Implementation Patterns

[Source: architecture/coding-standards.md]

**Constructor Pattern (Load by ID):**
```objectscript
Method %OnNew(pId As %String = "") As %Status
{
    Set tSC = $$$OK
    
    If pId '= "" {
        // Load existing row
        Set tSC = ..LoadFromDatabase(pId)
        If $$$ISERR(tSC) {
            // Handle load error
            Set ..Id = ""
        }
    } Else {
        // New instance
        Set ..%IsNew = 1
    }
    
    Quit tSC
}
```

**Save Pattern (Insert or Update):**
```objectscript
Method Save() As %Status
{
    Set tSC = $$$OK
    
    Try {
        If ..IsNew() {
            // INSERT new row
            &sql(INSERT INTO MyTable (Col1, Col2) 
                 VALUES (:..Property1, :..Property2))
            
            If (SQLCODE = 0) {
                Set ..Id = %ROWID
                Set ..%IsNew = 0
            }
        } Else {
            // UPDATE existing row
            &sql(UPDATE MyTable 
                 SET Col1 = :..Property1, Col2 = :..Property2
                 WHERE ID = :..Id)
        }
        
        If (SQLCODE '= 0) {
            Set tSC = $$$ERROR($$$GeneralError, "SQL Error: " _ SQLCODE)
        }
    } Catch ex {
        Set tSC = ex.AsStatus()
    }
    
    Quit tSC
}
```

**Finder Pattern (Class Method):**
```objectscript
ClassMethod FindById(pId As %String) As PatientRowGateway
{
    Set tGateway = ""
    
    Try {
        Set tGateway = ..%New(pId)
        If 'tGateway.IsNew() {
            // Successfully loaded
            Quit tGateway
        }
    } Catch ex {
        // Log error
    }
    
    Quit ""
}
```

- **Patient Row Access**: Gateway wrapping individual patient records

- **Instance Methods**:

- **State Tracking**: IsNew() and IsDirty() for change detection
- **Validation**: Ensure required fields present before save
- **Error Handling**: Proper error messages for invalid operations
- **Documentation**: Clear examples of row gateway usage patterns

### Row Data Gateway vs Other Data Source Patterns

- **Row Data Gateway vs Table Data Gateway**: Row has one instance per row with state; Table has one instance per table, stateless
- **Row Data Gateway vs Active Record**: Row gateway is pure data access; Active Record includes domain logic
- **Row Data Gateway vs Data Mapper**: Row gateway wraps database row; Data Mapper maps to rich domain objects
- **When to use Row Data Gateway**: Row-centric operations, need instance per row, simple CRUD without domain logic
- **When NOT to use**: Complex domain logic (use Active Record), table-wide operations (use Table Data Gateway), complex mapping (use Data Mapper)

### Class Structure Template for Row Data Gateway Pattern

[Source: architecture/coding-standards.md]
```objectscript
/// PoEAA Row Data Gateway Pattern - One instance per row
Class Patterns.PoEAA.DataSource.RowDataGateway Extends %RegisteredObject
{
    /// Row ID from database
    Property Id As %String;
    
    /// Flag indicating new (unsaved) instance
    Property %IsNew As %Boolean [ Private ];
    
    /// Constructor loads row by ID
    Method %OnNew(pId As %String = "") As %Status
    {
        Set tSC = $$$OK
        
        If pId '= "" {
            Set tSC = ..LoadFromDatabase(pId)
            If $$$ISERR(tSC) {
                Set ..Id = ""
                Set ..%IsNew = 1
            } Else {
                Set ..%IsNew = 0
            }
        } Else {
            Set ..%IsNew = 1
        }
        
        Quit tSC
    }
    
    /// Check if instance represents new (unsaved) row
    Method IsNew() As %Boolean
    {
        Quit ..%IsNew
    }
    
    /// Save row to database (insert or update)
    Method Save() As %Status
    {
        Set tSC = $$$OK
        
        Try {
            If ..IsNew() {
                Set tSC = ..InsertRow()
            } Else {
                Set tSC = ..UpdateRow()
            }
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        
        Quit tSC
    }
    
    /// Delete row from database
    Method Delete() As %Status
    {
        Set tSC = $$$OK
        
        Try {
            If ..IsNew() {
                Quit
            }
            
            Set tSC = ..DeleteRow()
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        
        Quit tSC
    }
    
    /// Refresh data from database
    Method Refresh() As %Status
    {
        Set tSC = $$$OK
        
        If ..IsNew() {
            Quit tSC
        }
        
        Set tSC = ..LoadFromDatabase(..Id)
        Quit tSC
    }
    
    /// Load row data from database (override in subclass)
    Method LoadFromDatabase(pId As %String) As %Status [ Private ]
    {
        Quit $$$OK
    }
    
    /// Insert new row (override in subclass)
    Method InsertRow() As %Status [ Private ]
    {
        Quit $$$OK
    }
    
    /// Update existing row (override in subclass)
    Method UpdateRow() As %Status [ Private ]
    {
        Quit $$$OK
    }
    
    /// Delete row (override in subclass)
    Method DeleteRow() As %Status [ Private ]
    {
        Quit $$$OK
    }
}
```

### SQL Injection Prevention

[Source: architecture/coding-standards.md]
- **ALWAYS use parameterized queries** with :param placeholders
- **NEVER concatenate user input into SQL strings**
- Use embedded SQL &sql() with :paramName syntax
- Validate and sanitize input before SQL execution
- Log all SQL execution failures for security auditing

### Error Handling Requirements

[Source: architecture/coding-standards.md]
- Return %Status from all methods that can fail
- Use $$$OK and $$$ERROR macros
- Check SQLCODE after every SQL operation
- Implement proper Try/Catch blocks
- Provide meaningful error messages with context
- **CRITICAL**: Cannot use argumented QUIT within Try/Catch blocks
  - Initialize return variable before Try
  - Set return value within Try
  - Use argumentless QUIT in Try/Catch
  - Return variable after Try/Catch block

### Performance Considerations

[Source: architecture/coding-standards.md]
- Use %OpenId() for efficient persistent object loading
- Cache gateway instances when appropriate
- Use indices for frequently queried columns
- Consider row-level locking for updates
- Profile SQL execution times for optimization
- Minimize property updates to reduce dirty tracking overhead

### Security Considerations

- Implement parameterized queries for all SQL (SQL injection prevention)
- Validate all input data before SQL execution
- Sanitize error messages to prevent information leakage
- Audit all data access operations for compliance
- Use appropriate SQL privileges for gateway operations
- Encrypt sensitive healthcare data per HIPAA requirements
- Log security events and suspicious operations
- Implement row-level security if required by use case

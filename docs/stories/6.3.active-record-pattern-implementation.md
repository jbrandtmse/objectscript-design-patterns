### Active Record Pattern Specific Considerations

- **Domain Object + Persistence**: Active Record combines domain logic with data access in single class
- **Extends %Persistent**: Leverage IRIS %Persistent class for automatic persistence capabilities
- **Instance Methods**: CRUD operations are instance methods (Save(), Delete(), Reload())
- **Business Logic**: Domain-specific methods coexist with persistence (Admit(), Discharge(), Transfer())
- **Validation**: Domain validation rules enforced in Save() method before persistence
- **Calculated Properties**: Derived values computed from stored properties (GetAge(), GetFullName())
- **Finder Methods**: Class methods return fully-populated active record instances
- **State Tracking**: %IsNew() built-in method identifies new vs existing records
- **Transaction Participation**: Active records participate in caller-managed transactions
- **Rich Domain Model**: Unlike gateways, active records contain business logic and rules

### IRIS %Persistent Class Features for Active Record

[Source: architecture/tech-stack.md, coding-standards.md]
- **%Save()**: Built-in method to persist object to database (handles INSERT/UPDATE automatically)
- **%Delete()**: Built-in method to remove object from database
- **%OpenId(id)**: Class method to load object by ID
- **%IsNew()**: Built-in method indicating if object exists in database
- **%Id()**: Property containing object's database ID
- **%Reload()**: Built-in method to refresh object from database
- **Properties**: Automatically mapped to SQL columns
- **Indices**: Define indices for query performance
- **SQL Projection**: Persistent classes automatically create SQL tables
- **Relationships**: One-to-many, many-to-one relationships supported
- **Callbacks**: %OnBeforeSave(), %OnAfterSave(), %OnDelete() for business logic hooks

### Active Record Implementation Patterns

[Source: architecture/coding-standards.md]

**Save Pattern (with Validation):**
```objectscript
Method Save() As %Status
{
    Set tSC = $$$OK
    
    Try {
        // Domain validation before save
        Set tSC = ..ValidateData()
        If $$$ISERR(tSC) {
            Quit
        }
        
        // Business rule checking
        Set tSC = ..CheckBusinessRules()
        If $$$ISERR(tSC) {
            Quit
        }
        
        // Persist to database using %Persistent
        Set tSC = ..%Save()
        
    } Catch ex {
        Set tSC = ex.AsStatus()
    }
    
    Quit tSC
}
```

**Business Logic Method Pattern:**
```objectscript
Method Admit(pDepartment As %String) As %Status
{
    Set tSC = $$$OK
    
    Try {
        // Validate business rule
        If (..Status '= "Pending") {
            Set tSC = $$$ERROR($$$GeneralError, "Patient must be in Pending status to admit")
            Quit
        }
        
        // Update domain state
        Set ..Department = pDepartment
        Set ..Status = "Admitted"
        Set ..AdmissionDate = $HOROLOG
        
        // Persist changes
        Set tSC = ..Save()
        
    } Catch ex {
        Set tSC = ex.AsStatus()
    }
    
    Quit tSC
}
```

**Finder Pattern (Class Method):**
```objectscript
ClassMethod FindById(pId As %String) As PatientActiveRecord
{
    Set tRecord = ""
    
    Try {
        // Use %OpenId() to load persistent object
        Set tRecord = ..%OpenId(pId)
        
    } Catch ex {
        // Log error
        Do ##class(Patterns.Utils.Logger).LogError("ActiveRecord", "FindById", ex.DisplayString())
    }
    
    Quit tRecord
}
```

**Calculated Property Pattern:**
```objectscript
Method GetAge() As %Integer
{
    Set tAge = 0
    
    If (..DateOfBirth '= "") {
        Set tToday = +$HOROLOG
        Set tBirthday = ..DateOfBirth
        Set tAge = ($PIECE(tToday, ",", 1) - $PIECE(tBirthday, ",", 1)) \ 365
    }
    
    Quit tAge
}
```

### Active Record vs Other Data Source Patterns

- **Active Record vs Row Data Gateway**: Active Record includes domain logic; Row Gateway is pure data access
- **Active Record vs Table Data Gateway**: Active Record is instance-based with logic; Table Gateway is stateless table operations
- **Active Record vs Data Mapper**: Active Record couples logic with persistence; Data Mapper separates them completely
- **When to use Active Record**: Simple domain models, straightforward persistence, business logic closely tied to data
- **When NOT to use**: Complex domain models (use Data Mapper), heavy business logic (use Domain Model + Mapper), stateless operations (use Table Gateway)

### Class Structure Template for Active Record Pattern

[Source: architecture/coding-standards.md]
```objectscript
/// PoEAA Active Record Pattern - Domain object with persistence
Class Patterns.PoEAA.DataSource.ActiveRecord Extends %Persistent [ Abstract ]
{
    /// Validate domain data before save
    Method ValidateData() As %Status
    {
        // Override in subclasses
        Quit $$$OK
    }
    
    /// Check business rules before save
    Method CheckBusinessRules() As %Status
    {
        // Override in subclasses
        Quit $$$OK
    }
    
    /// Save record to database with validation
    Method Save() As %Status
    {
        Set tSC = $$$OK
        
        Try {
            // Validate data
            Set tSC = ..ValidateData()
            If $$$ISERR(tSC) {
                Quit
            }
            
            // Check business rules
            Set tSC = ..CheckBusinessRules()
            If $$$ISERR(tSC) {
                Quit
            }
            
            // Persist using %Persistent
            Set tSC = ..%Save()
            
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        
        Quit tSC
    }
    
    /// Delete record from database
    Method Delete() As %Status
    {
        Set tSC = $$$OK
        
        Try {
            Set tSC = ..%DeleteId(..%Id())
            
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        
        Quit tSC
    }
    
    /// Reload data from database
    Method Reload() As %Status
    {
        Set tSC = $$$OK
        
        Try {
            Set tSC = ..%Reload()
            
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        
        Quit tSC
    }
    
    /// Find record by ID
    ClassMethod FindById(pId As %String) As ActiveRecord
    {
        Set tRecord = ""
        
        Try {
            Set tRecord = ..%OpenId(pId)
            
        } Catch ex {
            // Log error
        }
        
        Quit tRecord
    }
    
    /// Find all records
    ClassMethod FindAll() As %ListOfObjects
    {
        Set tList = ##class(%ListOfObjects).%New()
        
        Try {
            Set tSQL = "SELECT ID FROM " _ ..%ClassName(1)
            Set tStatement = ##class(%SQL.Statement).%New()
            Set tSC = tStatement.%Prepare(tSQL)
            
            If $$$ISOK(tSC) {
                Set tResult = tStatement.%Execute()
                While tResult.%Next() {
                    Set tRecord = ..%OpenId(tResult.%Get("ID"))
                    If $IsObject(tRecord) {
                        Do tList.Insert(tRecord)
                    }
                }
            }
            
        } Catch ex {
            // Log error
        }
        
        Quit tList
    }
}
```

### SQL Injection Prevention

[Source: architecture/coding-standards.md]
- **ALWAYS use parameterized queries** with :param or ? placeholders
- **NEVER concatenate user input into SQL strings**
- Use %SQL.Statement with parameterized queries for custom finders
- Built-in %Persistent methods (%OpenId, %Save, %Delete) are inherently safe
- Validate and sanitize input before SQL execution
- Log all SQL execution failures for security auditing

### Error Handling Requirements

[Source: architecture/coding-standards.md]
- Return %Status from all methods that can fail
- Use $$$OK and $$$ERROR macros
- Implement proper Try/Catch blocks
- Provide meaningful error messages with context
- **CRITICAL**: Cannot use argumented QUIT within Try/Catch blocks
  - Initialize return variable before Try
  - Set return value within Try
  - Use argumentless QUIT in Try/Catch
  - Return variable after Try/Catch block
- Check $$$ISOK and $$$ISERR for status values
- Log errors with sufficient context for debugging

### Performance Considerations

[Source: architecture/coding-standards.md]
- Use %OpenId() for efficient object loading by ID
- Leverage indices for frequently queried properties (MRN, LastName, Department)
- Cache active record instances when appropriate to reduce database hits
- Use %Save() efficiently - only save when changes made
- Consider lazy loading for related objects
- Profile business logic methods for optimization
- Use SQL queries for bulk operations instead of loading all active records

### Security Considerations

- Implement parameterized queries for custom finders (SQL injection prevention)
- Validate all input data in ValidateData() method
- Sanitize error messages to prevent information leakage
- Audit all data access operations for compliance
- Encrypt sensitive healthcare data per HIPAA requirements
- Log security events and suspicious operations
- Implement row-level security if required by use case
- Validate business rule transitions to prevent invalid state changes

### Class Structure Template for Transaction Script Pattern

[Source: architecture/coding-standards.md]
```objectscript
/// PoEAA Transaction Script Pattern - Organize Business Logic by Procedures
Class Patterns.PoEAA.DomainLogic.TransactionScript Extends %RegisteredObject
{
    /// Database connection property
    Property DatabaseConnection As %SQL.Connection;
    
    /// Transaction state tracking
    Property TransactionState As %String;
    
    /// Begin transaction
    Method StartTransaction() As %Status
    {
        Set tSC = $$$OK
        Try {
            // Start database transaction
            TSTART
            Set ..TransactionState = "ACTIVE"
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        Quit tSC
    }
    
    /// Commit transaction
    Method CommitTransaction() As %Status
    {
        Set tSC = $$$OK
        Try {
            TCOMMIT
            Set ..TransactionState = "COMMITTED"
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        Quit tSC
    }
    
    /// Rollback transaction
    Method RollbackTransaction() As %Status
    {
        Set tSC = $$$OK
        Try {
            TROLLBACK
            Set ..TransactionState = "ROLLED_BACK"
        } Catch ex {
            Set tSC = ex.AsStatus()
        }
        Quit tSC
    }
}
```

### Transaction Script Pattern Specific Considerations

- **Procedure Organization**: Each business operation is a separate procedure/method
- **Database Focus**: Pattern works well with table-oriented database operations
- **Simple Domain Logic**: Best for applications with minimal business logic complexity
- **Transaction Boundaries**: Each script method defines its own transaction scope
- **Error Handling**: Must handle rollback scenarios consistently
- **Testing**: Focus on testing individual procedures and transaction scenarios
- **Performance**: Efficient for simple CRUD operations
- **Scalability**: May not scale well with complex business rules

### IRIS Transaction Management Features

[Source: architecture/tech-stack.md]
- **TSTART**: Begin transaction (can be nested)
- **TCOMMIT**: Commit current transaction level
- **TROLLBACK**: Rollback current transaction level
- **$TLEVEL**: Current transaction nesting level
- **Automatic Rollback**: On unhandled errors or process termination
- **Lock Management**: Automatic lock management within transactions
- **Global Transactions**: Support for distributed transactions
- **Savepoints**: Named savepoints for partial rollback

### Healthcare Patient Admission Requirements

- **Patient Registration**: Demographics, insurance, emergency contacts
- **Bed Assignment**: Room availability, patient preferences, medical needs
- **Insurance Verification**: Coverage validation, prior authorization
- **Medical History**: Previous admissions, allergies, medications, conditions
- **Admission Workflow**: Sequential procedures with rollback capability
- **Compliance**: HIPAA audit trails, patient consent tracking
- **Performance**: Handle high-volume admission scenarios efficiently
- **Error Recovery**: Graceful handling of system failures during admission

### Transaction Script vs Other Domain Logic Patterns

- **Transaction Script vs Domain Model**: Script uses procedures, Domain Model uses rich objects
- **Transaction Script vs Table Module**: Script has one class per use case, Table Module has one class per table
- **Transaction Script vs Service Layer**: Script IS the service layer, Service Layer coordinates domain objects
- **When to use Transaction Script**: Simple domain logic, table-oriented operations, rapid development
- **When NOT to use**: Complex business rules, rich domain behavior, frequent rule changes

### Test Coverage Analysis

**Test Method Return Value Issue:**

Per `.clinerules/00-objectscript-testing.md`, test methods in ObjectScript must properly handle return values. The current implementation has test methods ending with `Quit` (no argument), but the framework expects either:

1. **Option A:** Return %Status explicitly:
```objectscript
Method TestStartTransaction() As %Status
{
    // ... test code ...
    Quit $$$OK
}
```

2. **Option B:** No return type with plain Quit:
```objectscript
Method TestStartTransaction()
{
    // ... test code ...
    Quit
}
```

**Current Issue:** Methods appear to be treated as functions requiring return values, but only provide argumentless `Quit` statements.

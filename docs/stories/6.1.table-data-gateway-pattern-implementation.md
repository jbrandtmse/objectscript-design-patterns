### Table Data Gateway Pattern Specific Considerations

- **One Gateway Per Table**: Each gateway class corresponds to a single database table
- **Encapsulates SQL**: All SQL queries contained within the gateway, hidden from callers
- **Returns Simple Data**: Methods return collections of data objects or primitive values, not domain objects
- **Stateless**: Gateways should be stateless; all table state in database
- **CRUD Operations**: Standard Create, Read, Update, Delete methods for table access
- **Finder Methods**: Custom query methods named Find* (FindByLastName, FindByDate, etc.)
- **Parameterized Queries**: MUST use parameterized queries to prevent SQL injection
- **Result Sets**: Process %ResultSet objects and return data structures
- **No Business Logic**: Gateways contain only data access code, no business rules
- **Transaction Neutral**: Gateways don't manage transactions; callers control transaction scope

### IRIS Embedded SQL Features

[Source: architecture/tech-stack.md, coding-standards.md]
- **&sql() Tag**: Use embedded SQL syntax: `&sql(SELECT * FROM Table WHERE ID = :pId)`
- **SQL Result Code**: Check SQLCODE after each SQL operation (0 = success, 100 = no data, <0 = error)
- **Parameterized Queries**: Use :paramName syntax for parameters (prevents SQL injection)
- **%ResultSet**: Process multi-row results using %SQL.Statement and %ResultSet
- **Dynamic SQL**: Use %SQL.Statement for programmatically constructed queries
- **SQL Projections**: Persistent classes automatically project to SQL tables
- **Table Names**: Format as Schema_Package.ClassName for persistent classes
- **SQL Functions**: Access to standard SQL functions plus IRIS extensions
- **Indices**: Leverage class indices for query performance

### IRIS SQL Execution Patterns

[Source: architecture/coding-standards.md]

**Simple Query (Single Result):**
```objectscript
Method FindById(pId As %String) As %DynamicObject
{
    Set tResult = ""
    
    &sql(SELECT ID, Name, Status INTO :id, :name, :status 
         FROM MyTable WHERE ID = :pId)
    
    If (SQLCODE = 0) {
        Set tResult = {}
        Set tResult.id = id
        Set tResult.name = name
        Set tResult.status = status
    }
    
    Quit tResult
}
```

**Multi-Row Query (Result Set):**
```objectscript
Method FindAll() As %ListOfDataTypes
{
    Set tList = ##class(%ListOfDataTypes).%New()
    Set tStatement = ##class(%SQL.Statement).%New()
    Set tStatus = tStatement.%Prepare("SELECT ID, Name FROM MyTable")
    
    Set tResult = tStatement.%Execute()
    While tResult.%Next() {
        Set tData = {}
        Set tData.id = tResult.%Get("ID")
        Set tData.name = tResult.%Get("Name")
        Do tList.Insert(tData)
    }
    
    Quit tList
}
```

**Parameterized Insert:**
```objectscript
Method Insert(pData As %DynamicObject) As %String
{
    Set tId = ""
    
    &sql(INSERT INTO MyTable (Name, Status) 
         VALUES (:pData.name, :pData.status))
    
    If (SQLCODE = 0) {
        Set tId = %ROWID
    }
    
    Quit tId
}
```

### Table Data Gateway vs Other Data Source Patterns

- **Table Data Gateway vs Row Data Gateway**: Table gateway has one instance for table; Row gateway has one instance per row
- **Table Data Gateway vs Active Record**: Table gateway is stateless data access; Active Record combines domain logic with persistence
- **Table Data Gateway vs Data Mapper**: Table gateway returns simple data; Data Mapper returns rich domain objects
- **When to use Table Data Gateway**: Simple CRUD, table-centric operations, stateless access, SQL encapsulation
- **When NOT to use**: Rich domain models (use Data Mapper), row-centric access (use Row Data Gateway), combined logic/persistence (use Active Record)

### Class Structure Template for Table Data Gateway Pattern

```objectscript
/// PoEAA Table Data Gateway Pattern - Encapsulate table access
Class Patterns.PoEAA.DataSource.TableDataGateway Extends %RegisteredObject
{
    /// Table name this gateway accesses
    Parameter TABLENAME;
    
    /// Find all records in table
    ClassMethod FindAll() As %ListOfDataTypes
    {
        Set tList = ##class(%ListOfDataTypes).%New()
        Set tStatement = ##class(%SQL.Statement).%New()
        Set tSQL = "SELECT * FROM " _ ..#TABLENAME
        Set tStatus = tStatement.%Prepare(tSQL)
        
        If $$$ISOK(tStatus) {
            Set tResult = tStatement.%Execute()
            While tResult.%Next() {
                // Map result to data object
                Set tData = ..MapResultToObject(tResult)
                Do tList.Insert(tData)
            }
        }
        
        Quit tList
    }
    
    /// Find record by ID
    ClassMethod FindById(pId As %String) As %DynamicObject
    {
        Set tResult = ""
        Set tStatement = ##class(%SQL.Statement).%New()
        Set tSQL = "SELECT * FROM " _ ..#TABLENAME _ " WHERE ID = ?"
        Set tStatus = tStatement.%Prepare(tSQL)
        
        If $$$ISOK(tStatus) {
            Set tRS = tStatement.%Execute(pId)
            If tRS.%Next() {
                Set tResult = ..MapResultToObject(tRS)

        Quit tResult
```

### Healthcare Patient Data Gateway Example

```objectscript
Class Patterns.Examples.Clinical.PatientDataGateway Extends Patterns.PoEAA.DataSource.TableDataGateway
{
    Parameter TABLENAME = "Patterns_Examples.Patient";
    
    /// Find all patients
    ClassMethod FindAllPatients() As %ListOfDataTypes
    {
        Quit ..FindAll()
    }
    
    /// Find patient by ID
    ClassMethod FindPatientById(pPatientId As %String) As %DynamicObject
    {
        Quit ..FindById(pPatientId)
    }
    
    /// Find patients by last name
    ClassMethod FindPatientsByLastName(pLastName As %String) As %ListOfDataTypes
    {
        Set tList = ##class(%ListOfDataTypes).%New()
        Set tStatement = ##class(%SQL.Statement).%New()
        Set tSQL = "SELECT * FROM Patterns_Examples.Patient WHERE LastName = ?"
        Set tStatus = tStatement.%Prepare(tSQL)
        
        If $$$ISOK(tStatus) {
            Set tResult = tStatement.%Execute(pLastName)
            While tResult.%Next() {
                Set tData = ..MapResultToObject(tResult)
                Do tList.Insert(tData)
            }
        }
        
        Quit tList
    }
    
    /// Insert new patient
    ClassMethod InsertPatient(pPatientData As %DynamicObject) As %String
    {
        Quit ..Insert(pPatientData)
    }
}
```

### SQL Injection Prevention

[Source: architecture/coding-standards.md]
- **NEVER concatenate user input into SQL strings**
- **ALWAYS use parameterized queries** with :param or ? placeholders
- Use %SQL.Statement.%Prepare() with parameterized SQL
- Use embedded SQL &sql() with :paramName syntax
- Validate and sanitize input before SQL execution
- Log all SQL execution failures for security auditing
- **Example - BAD (vulnerable to injection):**
  ```objectscript
  Set tSQL = "SELECT * FROM Patient WHERE Name = '" _ pName _ "'"
  ```
- **Example - GOOD (parameterized):**
  ```objectscript
  Set tSQL = "SELECT * FROM Patient WHERE Name = ?"
  Set tResult = tStatement.%Execute(pName)
  ```

### Error Handling Requirements

[Source: architecture/coding-standards.md]
- Return %Status from all methods that can fail
- Use $$$OK and $$$ERROR macros
- Check SQLCODE after every SQL operation:
  - SQLCODE = 0: Success
  - SQLCODE = 100: No data found (not necessarily an error)
  - SQLCODE < 0: Error occurred
- Implement proper Try/Catch blocks
- Provide meaningful error messages with context
- Log SQL errors with full query details (sanitized)
- Don't expose internal database structure in error messages
- **CRITICAL**: Cannot use argumented QUIT within Try/Catch blocks
  - Initialize return variable before Try
  - Set return value within Try
  - Use argumentless QUIT in Try/Catch
  - Return variable after Try/Catch block

### Performance Considerations

[Source: architecture/coding-standards.md]
- Use appropriate indices for frequently queried columns
- Leverage IRIS query optimizer with embedded SQL
- Use %SQL.Statement.%Prepare() once, execute multiple times
- Consider result set size for FindAll() operations
- Use COUNT(*) queries for statistics instead of fetching all rows
- Profile SQL execution times for optimization
- Cache connection/statement objects where appropriate
- Use batch operations for multiple inserts/updates

### Class Structure Template for Flyweight Pattern
[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four Flyweight Pattern - Memory Optimization
Class Patterns.GoF.Structural.Flyweight Extends %RegisteredObject
{
    /// Intrinsic state - shared among flyweights
    Property IntrinsicState As %String;
    
    /// Operation using extrinsic state
    Method Operation(pExtrinsicState As %String) As %String
    {
        // Combine intrinsic and extrinsic state
        Set tResult = "Intrinsic: "_..IntrinsicState_", Extrinsic: "_pExtrinsicState
        Quit tResult
    }
}

/// Flyweight Factory managing shared instances
Class Patterns.GoF.Structural.FlyweightFactory Extends %RegisteredObject
{
    /// Get or create flyweight
    ClassMethod GetFlyweight(pKey As %String) As Flyweight
    {
        // Check if exists in global pool
        If $DATA(^Patterns.Flyweight.Pool(pKey)) {
            // Return existing instance from pool
            Set tOID = ^Patterns.Flyweight.Pool(pKey)
            Quit ##class(Flyweight).%OpenId(tOID)
        }
        
        // Create new flyweight
        Set tFlyweight = ##class(ConcreteFlyweight).%New()
        Set tFlyweight.IntrinsicState = pKey
        
        // Store in global pool
        Set ^Patterns.Flyweight.Pool(pKey) = tFlyweight.%Id()
        
        Quit tFlyweight
    }
}
```

### Flyweight Pattern Specific Considerations
- **Intrinsic vs Extrinsic State**: Clear separation of shared vs context-specific data
- **Factory Pattern Integration**: Factory manages flyweight pool lifecycle
- **Global-based Pool**: Use IRIS globals for efficient shared object storage
- **Memory Optimization**: Significant memory savings with many similar objects
- **Thread Safety**: Ensure concurrent access to shared pool is safe
- **Reference Management**: Track usage to enable cleanup of unused flyweights
- **Performance Trade-off**: Small lookup overhead vs large memory savings
- **ObjectScript Globals**: Leverage native global structures for optimal caching

### Value Object Pattern Specific Considerations

- **Immutability**: Properties set only in constructor, cannot change afterward
- **Value Equality**: Two objects equal if all property values equal
- **Reference Equality**: Entities use ID; Value Objects use values
- **No Identity**: Value objects have no unique identifier
- **Validation**: Validate in constructor, ensure valid state
- **Collections**: Value objects safe in collections due to immutability
- **Copy Pattern**: Create new instance for "modifications"
- **ObjectScript Immutability**: Use Private setters or read-only properties

### Value Object Implementation Patterns

[Source: architecture/coding-standards.md]

**Immutability Pattern:**
```objectscript
Class VitalSigns Extends ValueObject
{
    Property Temperature As %Numeric [ Private ];
    Property HeartRate As %Integer [ Private ];
    
    Method %OnNew(pTemp As %Numeric, pHR As %Integer) As %Status
    {
        Set i%Temperature = pTemp
        Set i%HeartRate = pHR
        
        // Validate
        If (pTemp < 95) || (pTemp > 110) {
            Quit $$$ERROR($$$GeneralError, "Invalid temperature")
        }
        
        Quit $$$OK
    }
    
    // Public getters only
    Method TemperatureGet() As %Numeric
    {
        Quit i%Temperature
    }
    
    Method HeartRateGet() As %Integer
    {
        Quit i%HeartRate
    }
}
```

**Value-Based Equality:**
```objectscript
Method Equals(pOther As ValueObject) As %Boolean
{
    If '$IsObject(pOther) {
        Quit 0
    }
    
    If (pOther.%ClassName(1) '= ..%ClassName(1)) {
        Quit 0
    }
    
    // Compare all property values
    If (..Temperature '= pOther.Temperature) {
        Quit 0
    }
    
    If (..HeartRate '= pOther.HeartRate) {
        Quit 0
    }
    
    Quit 1
}
```

**Copy Pattern (for "modification"):**
```objectscript
Method WithTemperature(pNewTemp As %Numeric) As VitalSigns
{
    // Create new instance with modified value
    Quit ##class(VitalSigns).%New(pNewTemp, ..HeartRate)
}
```

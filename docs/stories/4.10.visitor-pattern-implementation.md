### Class Structure Template for Visitor Pattern

[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four Visitor Pattern - Add Operations to Object Structures
Class Patterns.GoF.Behavioral.Visitor Extends %RegisteredObject [ Abstract ]
{
    /// Visit method for each concrete element type
    Method VisitConcreteElementA(pElement As ConcreteElementA) [ Abstract ]
    {
        Quit
    }
    
    Method VisitConcreteElementB(pElement As ConcreteElementB) [ Abstract ]
    {
        Quit
    }
}

/// Element interface with Accept method
Class Patterns.GoF.Behavioral.Element Extends %RegisteredObject [ Abstract ]
{
    /// Accept a visitor - implements double dispatch
    Method Accept(pVisitor As Visitor) [ Abstract ]
    {
        Quit
    }
}

/// Concrete element implementation
Class Patterns.GoF.Behavioral.ConcreteElementA Extends Element
{
    Method Accept(pVisitor As Visitor)
    {
        // Double dispatch - element tells visitor its type
        Do pVisitor.VisitConcreteElementA($THIS)
    }
}
```

### Visitor Pattern Specific Considerations

- **Double Dispatch**: Key mechanism for type-specific operations
- **Open/Closed Principle**: Add operations without modifying elements
- **Element Stability**: Element hierarchy should be stable
- **Visitor Accumulation**: Visitors can accumulate state during traversal
- **Traversal Control**: Elements control traversal order
- **Breaking Encapsulation**: Visitors may need access to element internals
- **Circular Dependencies**: Visitor and Element hierarchies are interdependent
- **Adding Elements**: Difficult to add new element types (requires updating all visitors)

### ObjectScript-Specific Visitor Features

[Source: architecture/coding-standards.md]
- **Method Dispatch**: Use $CLASSMETHOD and $METHOD for dynamic dispatch
- **Type Checking**: Use %IsA() for runtime type verification
- **Object References**: Use $THIS for self-reference in Accept
- **Abstract Methods**: Must have body with Quit statement
- **Polymorphism**: Leverage ObjectScript's dynamic typing
- **Collection Traversal**: Support for %Collection classes
- **Performance**: Consider caching method references
- **Error Handling**: Proper Try/Catch for visitor operations

### Visitor vs Other Behavioral Patterns Differences

- **Visitor vs Strategy**: Visitor separates algorithm from object structure, Strategy encapsulates algorithms
- **Visitor vs Iterator**: Iterator traverses, Visitor performs operations during traversal
- **Visitor vs Command**: Command encapsulates requests, Visitor encapsulates operations on structures
- **Visitor vs Observer**: Observer notifies of changes, Visitor performs operations on existing structures
- **Visitor vs Template Method**: Template defines algorithm steps, Visitor defines operations on elements
- **When to use Visitor**: Stable element hierarchy, many unrelated operations, operations span multiple classes
- **When NOT to use**: Frequently changing element hierarchy, simple single operations

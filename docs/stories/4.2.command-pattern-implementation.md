### Class Structure Template for Command Pattern
[Source: architecture/coding-standards.md]
```objectscript
/// Gang of Four Command Pattern - Request Encapsulation
Class Patterns.GoF.Behavioral.Command Extends %RegisteredObject
{
    /// Reference to the receiver object
    Property Receiver As Receiver;
    
    /// Command parameters
    Property Parameters As %DynamicObject;
    
    /// Execution timestamp
    Property ExecutedAt As %TimeStamp;
    
    /// Previous state for undo
    Property PreviousState As %DynamicObject;
    
    /// Execute the command
    Method Execute() As %Status [ Abstract ]
    {
        Quit $$$OK
    }
    
    /// Undo the command
    Method Undo() As %Status [ Abstract ]
    {
        Quit $$$OK
    }
    
    /// Check if command can be executed
    Method CanExecute() As %Boolean
    {
        Quit 1  // Default: can execute
    }
    
    /// Store state before execution
    Method CaptureState() As %Status
    {
        Set ..PreviousState = ..Receiver.GetState()
        Quit $$$OK
    }
}
```

### Command Pattern Specific Considerations
- **Command Encapsulation**: All request information in command object
- **Undo/Redo Support**: State management before/after execution
- **Command Queue**: Support for deferred and batched execution
- **History Management**: Limited history size to prevent memory issues
- **Receiver Decoupling**: Commands work through receiver interface
- **Parameter Validation**: Validate before execution, not construction
- **Transaction Support**: Group commands in transactions
- **Error Recovery**: Graceful rollback on failure

### Healthcare Clinical Order Requirements
- **Order Types**: Lab, Medication, Imaging, Procedure orders
- **Order States**: Draft, Pending, Active, Completed, Cancelled
- **Undo Constraints**: Some orders cannot be undone after certain states
- **Audit Requirements**: Complete audit trail of all changes
- **Priority Levels**: Routine, Urgent, STAT handling
- **Approval Chain**: Some orders require approval before execution
- **Time Sensitivity**: Order expiration and time-based constraints
- **Conflict Detection**: Check for medication interactions, duplicate orders

### ObjectScript Method References
[Source: architecture/coding-standards.md]
- **Method References**: Use ##class(ClassName).Method() syntax
- **Instance Methods**: Use ..Method() for current instance
- **Dynamic Dispatch**: Use $METHOD(object, methodName, args...)
- **ClassMethod References**: Store as strings, execute with $CLASSMETHOD()
- **Callback Pattern**: Pass class and method names as parameters
- **Method Existence**: Check with $CLASSMETHOD validity
- **Performance**: Cache method references where possible
